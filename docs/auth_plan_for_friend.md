# دليل تفعيل نظام الحماية المتقدم (Supabase Auth Migration)

مرحباً يا صديقي 👋
عبد الله طلب مني مساعدته في تأمين الموقع بأقصى درجة ممكنة "مثل الشركات الكبيرة".
لقد قمت بإنشاء ملفات SQL لتأمين الجداول (RLS)، ولكن لكي تعمل هذه الحماية، نحتاج لتغيير نظام تسجيل الدخول من `LocalStorage` (الحالي) إلى `Supabase Auth` (الحقيقي).

إليك الخطوات المطلوبة منك كمسؤول عن قاعدة البيانات (Supabase Admin):

## 1. تفعيل تسجيل الدخول (Enable Auth Providers)
1. ادخل على لوحة تحكم Supabase > **Authentication** > **Providers**.
2. فعل خيار **Email**.
3. تأكد من أن **Email / Password** مفعل.
4. (اختياري) قم بتعطيل "Confirm email" من إعدادات الـ Auth إذا كنت تريد تجربتها بسرعة بدون تأكيد إيميلات.

## 2. إنشاء مستخدم "المشرف" (Create Professor User)
1. اذهب إلى **Authentication** > **Users**.
2. اضغط **Add User**.
3. قم بإنشاء حساب جديد ببيانات عبد الله (مثلاً):
   - **Email:** `admin@dwd.com` (أو إيميله الحقيقي)
   - **Password:** (اختر كلمة مرور قوية واكتبها لعبد الله)
4. بمجرد إنشاء المستخدم، انسخ الـ **User UID** الخاص به (سنحتاجه لتمييزه كمشرف).

## 3. وضع صلاحيات المشرف (Set Admin Role)
نحتاج لتمييز هذا المستخدم كـ "دكتور/مشرف" في التداول.
1. اذهب إلى **Table Editor** > جدول `doctors` (أو `users` حسب تصميمك).
2. إذا كان جدول `doctors` بسيطاً (قائمة إيميلات)، فقط أضف إيميله فيه.
3. **الأفضل:** أن نعتمد على الـ UUID.
   - إذا لم يكن لديك جدول للصلاحيات، يمكنك استخدام دالة `is_admin` في الـ SQL (سأشرحها لاحقاً) أو ببساطة، أي شخص نضيفه في جدول `doctors` يعتبر مشرف.

## 4. تنفيذ ملف الحماية (Run SQL Security)
بعد تجهيز المستخدم:
1. اذهب إلى **SQL Editor**.
2. انسخ محتوى ملف `supabase_security.sql` (الذي أرسله لك عبد الله).
3. اضغط **Run**.

## 5. (مهم جداً للمطور) بيانات الربط
عبد الله يحتاج منك البيانات التالية ليضعها في الكود الجديد:
1. **Project URL**: (مثل `https://xyz.supabase.co`)
2. **Project API Key (Anon Public)**: (الذي يبدأ بـ `ey...`)

رعاك الله، وشكراً لمجهودك في هذا المشروع الجميل! 🚀
