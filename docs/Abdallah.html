خطة الطوارئ (السبت - الخميس)

📅 الليلة + الإثنين (التركيز على الـ )

امتحان الـ محتاج حفظ وفهم للخوارزميات. بما إنك عندك خلفية برمجية، ركز على:

  • فيديوهات شرح Process Scheduling (FCFS, SJF, Round Robin).
  • فهم الـ Deadlocks وكيفية تجنبها.
  • الفرق بين Process و Thread.
  • ذاكر الـ بنسبة 70% من وقتك في اليومين دول.
  • الـ 30% الباقية: اقرأ هذا الملف وتصفح كود المشروع قراءة فقط.

📅 الثلاثاء (يوم الكود العملي)

اليوم ده مخصص للمشروع والـ Web:

  • اتفرج على فيديوهات عن الـ SPA (Single Page Application) و DOM Manipulation.
  • افتح ملف server.js وحاول تغير رسالة بسيطة وتعمل npm start وتشوف التغيير (ده هيديك ثقة).
  • راجع "شرح الكود" الموجود في الأسفل بالتفصيل.

📅 الأربعاء (ليلة الامتحان والمناقشة)

مراجعة نهائية وهدوء:

  • الصبح: مراجعة سريعة لقوانين الـ ومسائل الـ Scheduling.
  • بالليل: جهز اللابتوب، اتأكد إن المشروع شغال (Run npm start)، وجهز جملتين تتكلم بيهم عن دورك في المشروع.
  • نام بدري! التركيز أهم من المذاكرة لغاية الصبح.

شرح الكود (عشان لما الدكتورة تسألك)

دي أهم الأجزاء اللي استخدمناها في المشروع، مشروحين ببساطة عشان لو اتسألت "الكود ده بيعمل إيه؟".

1. السيرفر (server.js) ودور Node.js

احنا استخدمنا Node.js عشان نعمل "سيرفر بسيط" يشغل الموقع ويتحكم في البيانات.

سؤال متوقع: "ليه استخدمتوا Node.js؟"
الإجابة: "عشان هو بيسمح لنا نستخدم JavaScript في الـ Backend والـ Frontend، وده بيسهل الربط بينهم. كمان هو سريع في التعامل مع الـ API." 
const express = require('express'); // مكتبة لعمل السيرفر بسهولة
const app = express();

// ده اسمه Endpoint أو رابط الـ API
// لما الفرونت إند يطلب البيانات، السيرفر بيرد عليه من هنا
app.pt('/api/data', (req, res) => {
    // req = الطلب اللي جاي من المستخدم
    // res = الرد اللي السيرفر هيرسله
    res.json({
        users: LOCAL_USERS, // بنرجّع قائمة المستخدمين
        doctors: DOCTOR_ACCOUNTS // وقائمة الدكاترة
    });
});

2. جلب البيانات (Fetch API)

إزاي الصفحة بتجيب البيانات من السيرفر من غير ما تفضل ثابتة؟ بنستخدم دالة اسمها fetch.

سؤال متوقع: "يعني إيه Async / Await؟"
الإجابة: "يعني الكود بيستنى (Await) البيانات تيجي من السيرفر (لأنها بتاخد وقت) قبل ما يكمل تنفيذ باقي الأوامر، عشان مايحصلش خطأ وإن الصفحة تهنج." 
async function getData() {
    try {
        // بنطلب البيانات من الرابط ده
        const response = await fetch('http://localht:3000/api/data');
        
        // بنحول البيانات اللي جت لـ JSON (صيغة بيفهمها الجافاسكريبت)
        const data = await response.json();
        
        // console.log(data); // هنا البيانات بقت معانا نقدر نعرضها  [Security Fix]
    } catch (error) {
        console.error("حصل خطأ في الاتصال!", error);
    }
}

3. التخزين المحلي (LocalStorage)

ليه لما بعمل ريفرش مش بخرج من الموقع؟ عشان بنحفظ بيانات الدخول في "ذاكرة المتصفح". 

// حفظ البيانات (زي ما بنشيل حاجة في الدرج)
localStorage.setItem("currentUser", JSON.stringify(userObject));

// استرجاع البيانات (زي ما بنفتح الدرج نطلع الحاجة)
const user = JSON.parse(localStorage.getItem("currentUser"));

// لو مفيش يوزر، رجعه لصفحة تسجيل الدخول
if (!user) {
    window.location.href = "index.html";
}

4. التنقل السلس (SPA / Swup.js)

لاحظت إن الانتقال بين الصفحات ناعم ومش بيعمل وميض أبيض؟ ده بسبب تقنية Single Page Application (SPA) باستخدام مكتبة اسمها Swup.js.

الفكرة: المكتبة دي بتغير بس الجزء اللي في النص (المحتوى) وبتسيب الهيدر والفوتر ثابتين، فالموقع بيبقى أسرع وأشيك. 
// تعريف المكتبة وتحديد "الحاوية" اللي هتتغير
const swup = new Swup({
    containers: ['#swup-main'] // أي حاجة جوه الـ div ده هتتغير لما نضغط على رابط
});

5. دوال المصفوفات (Array Methods)

بما إنك عارف الـ Loops، فيه طرق أحدث وأشيك للتعامل مع البيانات (Arrays):

  • .find(): بتدور على عنصر واحد (زي لما تدور على يوزر بالإيميل بتاعه).
  • .filter(): بتصفي البيانات (زي لما تجيب الطلاب الناجحين بس).
  • .map(): بتحول البيانات لشكل تاني (زي تحويل قائمة بيانات لكروت HTML).
// مثال: البحث عن مستخدم
const foundUser = users.find(u => u.email === "me@test.com");

// مثال: فلترة الدرجات
const highScores = students.filter(s => s.score > 50);
